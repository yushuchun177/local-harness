local-harness 1.2.0  使用说明
================================================

完全离线的本地大模型对话。模型、对话记录、推理过程都在你的电脑里，
不联网、不登录、不上传。绿色免安装：拷到 U 盘里插到别的电脑上照常用。

开源：GNU GPL v3（见程序目录的 LICENSE）。运行时只调用 llama.cpp（MIT）。


一、第一次使用
----------------------------------------------
1) 双击「local-harness.exe」。
2) 第一次启动要加载模型，等十秒左右（中间会显示加载动画）。
3) 在下方输入框打字，回车发送。

程序目录里应该长这样：

    local-harness.exe
    _internal\      运行库（不要删、不要改名）
    llama\          llama.cpp 运行文件（不要删）
    model\          模型文件，.gguf 放这里
    chats\          你的对话记录（可以备份，也可以整个删掉）
    config.json     界面和参数设置


二、模型：任何 GGUF 都能用
----------------------------------------------
把 .gguf 文件放进 model\ 目录，重启程序就会出现在顶部的模型下拉框里；
也可以用顶部「导入」按钮，选一个放着模型的文件夹，程序会记住它。

支持 llama.cpp 能跑的所有模型，不限于某一家：

    Qwen 系列（Qwen2.5 / Qwen3 / Qwen3-Coder）
    Llama 系列（Llama 2 / 3 / 3.1 / 3.2，TinyLlama）
    Mistral / Mixtral / Gemma / Phi / DeepSeek / Yi / GLM / MiniCPM
    SmolLM / Granite / OLMo / Command R / StarCoder …

程序会自己读 GGUF 文件头，所以：

  · 模型名称自动整理成看得懂的样子（qwen3-1.7b-q8_0 → Qwen3 1.7B · Q8_0）
  · 「上下文」滑块的上限 = 该模型自己声明的原生上下文
  · 自动跳过不是聊天模型的文件：mmproj / 视觉投影 / 向量化模型 / 分片文件的
    第 2 片以后（分片模型只需放第 1 片，程序会自动找其余分片）
  · 模型自带的控制标记（<|im_end|> 之类）不会漏进气泡

推荐（按电脑配置挑一个）：

    Qwen3-0.6B-Q8_0        约 640MB   最轻快，普通办公本能跑
    Qwen3-1.7B-Q8_0        约 1.8GB   更聪明一些，8GB 内存够用
    Qwen2.5-3B-Instruct    约 2.1GB   再聪明一点，建议 16GB 内存
    Llama-3.2-1B-Instruct  约 800MB   非中文为主，但生态通用
    SmolLM2-360M-Instruct  约 370MB   最小，适合试水

一个对话只能用一个模型，切换模型会自动重新加载。
模型文件由各自发布方授权（例如 Qwen 系列是 Apache-2.0），本程序不附带模型，
只负责在本机调用它。


三、界面与快捷键
----------------------------------------------
顶部：模型选择、参数（温度 / 上下文 / 回复上限）、思考模式开关、
      关于、设置、深色/浅色切换。
左侧：对话列表。右键可以重命名或删除，× 直接删。
中间：消息区。助手回答是流式的，逐字出现。
底部：输入框与发送按钮（生成中变成「停止 ■」）。

    Enter            发送
    Shift + Enter    换行
    Ctrl + Enter     发送
    Esc              停止生成
    Ctrl + L         清空输入框


四、参数怎么调
----------------------------------------------
温度（0 ~ 2）
    越低越稳、越保守；越高越发散、越有创意。写代码 0.2~0.6，
    日常问答 0.7，写文案 0.9~1.2。

上下文（上下文窗口）
    这次对话能"记住"多少 token。上限是模型自身的能力（状态行会显示
    "原生 xxxx"），调得越大越占内存。

回复上限
    一次回答最多生成多少 token。回答被截断就调大，想更快就调小。

思考模式
    给支持思考的模型（如 Qwen3）开启"先思考再回答"。思考过程不会出现在
    气泡里，只显示最终回答；不支持思考的模型打开也不影响。

参数框里的数字可以直接改，也可以拖滑块，改完立刻生效；
改动会跟着 config.json 保存，下次打开还是这套设置。


五、对话与隐私
----------------------------------------------
· 没有账号，没有网络请求：程序不包含任何联网代码，断网也能用。
· 对话保存在程序目录的 chats\ 里，一个对话一个 .json 文件。
· 删掉 chats\ 里的文件即删掉对应对话；整个目录拷走就是完整备份。
· 换电脑：连 model\ 一起拷过去即可，绿色免安装。


六、常见问题
----------------------------------------------
问：双击没反应 / 一闪就退。
答：多半是 _internal\ 或 llama\ 被移动、被杀毒软件隔离了。
    把整个文件夹重新解压一份再试。

问：提示"还没有模型文件"。
答：把 .gguf 放进 model\ 目录，或点顶部「导入」选文件夹，然后重启程序。

问：我下的模型选项里没有。
答：确认是 .gguf 格式、体积大于 20MB、不是 mmproj 或向量模型；
    分片模型只需第 1 片（xxx-00001-of-00002.gguf）。

问：某个模型回答很差 / 一直重复。
答：小模型能力有限；可以调低温度、换大一点的模型。没有对话模板的模型
    回答会比较生硬，这属于模型本身的问题。

问：回答很慢。
答：换小一点的模型；在「设置」里把线程数设成 CPU 核心数；笔记本插电。

问：回答被截断了。
答：把「回复上限」调大（例如 2048）。

问：聊久了会变慢或者提示上下文不够。
答：程序会自动把较早的对话压缩成摘要（默认开启，阈值 2048 token，
    可以在「设置」里关掉或调整）。

问：能商用吗？
答：本程序是 GPLv3 自由软件，可以自由使用、修改、分发（分发时保留许可与
    源码）。模型请遵守各自发布方的许可（Qwen 系列 Apache-2.0，允许商用）。


七、目录里的东西都是干什么的
----------------------------------------------
local-harness.exe 主程序（窗口版）
_internal\        Python 运行时、tk 界面库、标准库
llama\            llama.cpp 的 llama-cli 和配套 DLL（推理引擎）
model\            你的 .gguf 模型
chats\            对话记录
config.json       界面与参数设置（删掉就恢复默认）


八、单文件版（只有一个 exe）
----------------------------------------------
如果你拿到的是"单文件版"，那就只有一个 local-harness.exe：

  local-harness-1.2.0-单文件.exe              42.8MB
  local-harness-1.2.0-单文件-含Qwen3-0.6B.exe  625MB（模型已经塞在里面）

用法和绿色版完全一样：
  · 启动后会在 exe 旁边生成 config.json 和 chats\（对话记录都放这里）
  · 模型放在 exe 旁边的 model\ 文件夹里，或用顶部「导入」选一个文件夹
  · 换个位置、拷到 U 盘，只需要带走这个 exe（模型在就一起带走）

两个版本的区别：
  · 42.8MB 那个只装程序和推理引擎，模型要自己放，启动不到 1 秒；
  · 625MB 那个连 Qwen3-0.6B 一起打包了，双击就能聊、什么都不用配，
    但每次启动都要先把模型解压到临时目录，等 15 秒左右（有启动画面顶着）。


九、显卡加速（CUDA / Vulkan / 张量核心）
----------------------------------------------
程序自带三套推理后端，放在程序目录下，界面里可以自由切换：

    llama\            CPU（纯处理器）
    llama-cuda\       CUDA（NVIDIA 显卡）
    llama-vulkan\     Vulkan（NVIDIA / AMD / Intel 都能用）

切换位置：顶部「设置」→「加速（显卡）」。

  · 加速方式：自动 / 纯 CPU / CUDA / Vulkan
    「自动」会按检测结果挑一个稳妥的：有 Vulkan 就用 Vulkan，否则 CUDA，再否则 CPU。
  · GPU 层数：全部层 / 0 层 / 4 / 8 / 12 / 16 / 20 / 24 / 32 层
    选「全部层」= 整个模型放显卡；选中间层数 = 显卡放一部分、CPU 放剩下的，
    这就是组合使用（显存小、模型大时最有用）。
  · 张量核心：显卡计算能力 ≥ 7.0（RTX 20 系及以后、V100/A100 等）时可用；
    不支持的卡会自动置灰并给出原因。它是通过 CUDA 的 MMQ 量化内核 +
    fp16 矩阵乘用上 Tensor Core 的，llama.cpp 没有单独的开关。
  · FlashAttention：CUDA / Vulkan 下建议开启，长上下文更快。
  · 界面底部状态栏会显示当前实际生效的方式，例如
    「Qwen3 1.7B · Q8_0 · Vulkan · 全部层 · 上下文 8192 原生 40960」。

本机（GTX 1050 Ti 4GB，计算能力 6.1，无张量核心）实测，Qwen3-1.7B：

    CPU        13.7 字/秒
    CUDA       48.6 字/秒   （全部层）
    Vulkan     59.0 字/秒   （全部层，推荐）

显存不够时（比如 4GB 卡跑 3B 模型）请用「12 层 + CPU」这类组合，
否则会加载失败或非常慢。
